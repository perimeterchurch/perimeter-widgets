Bypasses the loader and embeds /local/mission-trip-finder/index.js directly. Build first: pnpm --filter @perimeter/widget-mission-trip-finder build. data-api-url points at a local perimeter-api on :5500 — run pnpm dev there.

1 — the finder, with the detail opening in place

Click a card: it should fade to the trip's detail view without leaving the page, and the URL should gain ?trip-screen=detail&trip-id=…. Back returns to the grid. Inside the widget the cards must stay a plain grid (no bullets, no 2rem row gaps), banners and team avatars must have no red border and no grayscale, and buttons must stay brand blue rather than lime. On the detail, every team avatar must be visible — none stranded invisible, and the cover photo must span the full page width — past this container's 90px padding, edge to edge — without introducing a horizontal scrollbar.

2 — pinned to one trip (what a details page embeds)

data-trip-id="958" renders that trip's detail alone: no grid behind it, no Back button, and the URL is never written to. This is the mode that replaces the widget on the WordPress go-journey-details page.
