# event-finder

A responsive grid of upcoming events pulled from one or more Ministry Platform
**Events Lists**. Each card shows the title, date/time, location, an optional
image and description, and an optional "See Details" link. Rebuild of the legacy
`reactwidgets` EventFinder (which called the `api_custom_Event_Finder` stored
proc) on the perimeter-api backend.

Events are filtered to the configured list(s) and, by default, to **upcoming**
events only (sorted by start date). Set `data-include-past` to show past events.

## Embed

```html
<script src="https://widgets.perimeter.org/loader.js" async></script>
<div data-perimeter-widget="event-finder" data-list-id="18,208"></div>
```

## Config

The widget reads its config from `data-*` attributes on the placeholder div.
`src/types.ts` holds the zod schema (the source of truth for options and
defaults).

| Attribute                | Type     | Default               | Description                                                                                        |
| ------------------------ | -------- | --------------------- | -------------------------------------------------------------------------------------------------- |
| `data-list-id`           | string   | —                     | One or more MP Events List IDs, comma-separated (e.g. `18,208`). Required.                         |
| `data-show-images`       | boolean  | `false`               | Show each event's image (falls back to a placeholder when none).                                   |
| `data-show-location`     | boolean  | `true`                | Show the event's location name.                                                                    |
| `data-show-details`      | boolean  | `true`                | Show the "See Details" link (only when the event has one).                                         |
| `data-show-description`  | boolean  | `false`               | Show the event description (rendered as HTML from MP).                                             |
| `data-description-limit` | number   | `260`                 | Truncate the description to this many characters.                                                  |
| `data-alt-date`          | boolean  | `false`               | Use the compact date format (weekday, month day, time).                                            |
| `data-include-past`      | boolean  | `false`               | Include past events (default shows upcoming only).                                                 |
| `data-show-full-series`  | boolean  | `true`                | Show every occurrence of a recurring series. Set `false` to collapse each series to its next date. |
| `data-congregation-id`   | number   | —                     | Filter to one congregation (MP Congregation ID).                                                   |
| `data-program-id`        | number   | —                     | Filter to one program (MP Program ID).                                                             |
| `data-tier-id`           | string   | —                     | Filter to one or more Tier IDs, comma-separated.                                                   |
| `data-featured`          | boolean  | `false`               | Only show events featured on the calendar.                                                         |
| `data-signup-type`       | `1`\|`2` | —                     | `1` = open online registration, `2` = active volunteer opportunity.                                |
| `data-month`             | number   | —                     | Only show events starting in this month (1-12).                                                    |
| `data-keyword`           | string   | —                     | Search event titles and descriptions.                                                              |
| `data-max-events`        | number   | —                     | Cap the total number of events shown (at most 100 render; the widget requests one page of 100).    |
| `data-details-label`     | string   | `See Details`         | Text for the details link.                                                                         |
| `data-empty-message`     | string   | `No upcoming events.` | Message shown when the list has no events.                                                         |
| `data-default-image-url` | string   | —                     | Fallback image URL for events without their own image.                                             |
| `data-api-url`           | string   | —                     | Override the perimeter-api base URL (advanced).                                                    |

Beyond these filters, the endpoint always restricts to **public** (`Visibility_Level_ID = 4`), non-cancelled events, and — unless `data-include-past` is set — events that have not yet ended.

## Recurring series and per-series rules

A recurring event created with MP's **Create Series** tool is one series: every
date is its own Event record, linked together by MP. By default the finder shows
every upcoming date; `data-show-full-series="false"` collapses every series on
the list to a single card (its next date).

For finer control, staff set **Series Rules** on the Events List record in MP
(Events Lists → open the list → _Series Rules_ sub-page → New). Pick the series
from the dropdown, leave **Include Series** checked, and set **Max Upcoming**:

| Max Upcoming | Effect for that series on that list                          |
| ------------ | ------------------------------------------------------------ |
| blank        | Every upcoming date, even if the embed collapses series.     |
| `1`          | One card — the next date.                                    |
| `N`          | The next N dates.                                            |

**Include Series** (checked by default) makes the rule itself put the series on
the list: every date of the series shows in the finder (subject to Max
Upcoming) without anyone adding dates to the list one by one, and new dates MP
creates for the series appear automatically. Uncheck it only when a list
deliberately holds a hand-picked subset of a series and you just want to cap
those dates.

Rules are per list, so the same study can be "every date" on the Women's
Ministry page and "next date only" on a campus-wide page. A series with no rule
follows the embed's `data-show-full-series` setting. Rules live in MP, so they
apply to every embed of that list with no HTML change.

Two things staff should know:

- Only series built with the Create Series tool appear in the dropdown. Events
  created by copying one event several times are not linked in MP, so the finder
  treats each as a standalone event and they cannot be grouped or capped.
- `data-max-events` still caps the total after series rules are applied.

## Data source

`GET /api/events?listId=…` (perimeter-api). The endpoint resolves events from the
`Events_Lists_Events` join table, reads the `Events` records with their
location and detail-type, and reads each event's series and the list's series
rules from MP. Images are served from `GET /api/event-image/{id}`
(the event's default MP image). Backend details:
perimeter-api `docs/domains/events.md`, "Event-finder series".
