# frontier-pledge

A single dark band that collects a three-year pledge to the Frontier campaign:
first and last name, an optional spouse name, email, mobile, and the total
pledge amount. On submit it creates the Pledges row in Ministry Platform and
covers the form with a confirmation.

This is the port of the standalone `FrontierPledge` widget from the legacy
`reactwidgets` repo onto the shared runtime. Same design, same fields, same MP
note format — what changed is everything around it: the widget mounts through
`defineWidget`/`autoMount` into a shadow root, is styled from `@perimeter/theme`
tokens and `@perimeter/ui` components rather than hard-coded hexes, talks to
perimeter-api through the typed `useCreatePledge` hook instead of a hand-rolled
`fetch`, and reads its copy from `data-*` attributes instead of literals in the
JSX.

## Embed

```html
<script src="https://widgets.perimeter.org/loader.js" async></script>
<div data-perimeter-widget="frontier-pledge"></div>
```

The defaults are the live Frontier campaign, so the bare placeholder above is
the production embed. Everything below is for re-running the appeal on a
different period.

## Config

The widget reads its config from `data-*` attributes on the placeholder div.
`src/types.ts` is the source of truth.

| Attribute           | Required | Default                                  | Description                                                       |
| ------------------- | -------- | ---------------------------------------- | ----------------------------------------------------------------- |
| `data-pledge-campaign-id` | No | Frontier (`960`)                       | MP `Pledge_Campaign_ID` the pledge is recorded against.           |
| `data-heading`      | No       | `My 3-Year Pledge`                       | Headline above the form.                                          |
| `data-period`       | No       | `Jan 2026 - Dec 2028`                    | Pledge period, shown in brand amber under the headline.           |
| `data-amount-label` | No       | `Total 3-Year Pledge Amount`             | Label on the amount field.                                        |
| `data-account-url`  | No       | `https://www.perimeter.org/my-perimeter/`| Where the confirmation links a pledger to check their pledge. Set it to an empty value to drop that sentence. |
| `data-thank-you-heading` | No  | `Thank you for your pledge to the Frontier Campaign!` | Heading on the confirmation.                      |
| `data-api-url`      | No       | `https://api.perimeter.org`              | Override the perimeter-api base URL (advanced / local dev).       |

### Colors

Every color is optional and takes a hex value (`#1d4d3f` or `#fff`). Leave one
off and the Perimeter brand color is used; a value that isn't a hex color is
ignored the same way, so a typo never breaks the form. These exist so a host
page with its own brand — a church plant's page, say — can re-skin the band.

| Attribute                | Default            | Colors                                                       |
| ------------------------ | ------------------ | ------------------------------------------------------------ |
| `data-background-color`  | brand navy         | The band behind the form and the confirmation.               |
| `data-text-color`        | white              | Headline, field labels, confirmation text.                   |
| `data-heading-color`     | the text color     | The headline only.                                           |
| `data-accent-color`      | brand amber        | The pledge period and the Make Pledge button.                |
| `data-period-color`      | the accent color   | The pledge period only.                                      |
| `data-button-text-color` | brand navy         | The Make Pledge button's label.                              |

```html
<div
  data-perimeter-widget="frontier-pledge"
  data-background-color="#1d4d3f"
  data-text-color="#f4efe3"
  data-accent-color="#e07a5f"
  data-button-text-color="#ffffff"
></div>
```

Check contrast when choosing them: validation messages stay a light red tuned
for the dark navy band, so a light background color makes them hard to read.

### Pledging to another campaign

`data-pledge-campaign-id` points the form at a different MP campaign — a church
plant's, for example. It is safe to expose because perimeter-api decides which
campaigns accept pledges, not the page: `POST /api/giving/pledges` refuses
(400) any campaign that

- does not have **Allow Online Pledge** switched on in MP,
- is a mission trip (a trip pledge is a trip registration), or
- has passed its end date (unless **Pledge Beyond End Date** is on).

So before a page can use a new campaign, someone has to switch on **Allow
Online Pledge** on that campaign in MP. Until then the form shows its submit
error. A campaign id that isn't a whole number stops the widget from loading,
rather than quietly sending the pledge to Frontier.

A church plant embed usually changes the copy and colors too:

```html
<div
  data-perimeter-widget="frontier-pledge"
  data-pledge-campaign-id="887"
  data-heading="Plant Pledge"
  data-period="Jan 2027 - Dec 2029"
  data-thank-you-heading="Thank you for your pledge!"
  data-account-url=""
  data-background-color="#1d4d3f"
></div>
```

The host page's domain must also be in perimeter-api's widget origin
allowlist (`WIDGET_ORIGIN_ALLOWLIST` in `src/proxy.ts`), or every submit
fails with a CORS error. perimeter.org pages are already allowed.

## Behavior

- **Validation** — every field is validated in the widget
  (`src/lib/pledge.ts`), not by the browser: the form renders on the navy band,
  where a native validation bubble is off-brand and easy to miss. Messages
  appear per field in fixed-height slots, so nothing reflows as the form is
  checked, and a field's message clears as soon as that field is edited.
- **Amount** — typed freely, grouped to `12,500.00` when the field is left and
  ungrouped on the way back in. A pledge of 0 is rejected.
- **Spouse** — optional, and the only field that does not map to a column: it is
  folded into the MP note as a `Spouse: …` line, which is where staff read it.
- **Submit** — `POST /api/giving/pledges`. The API matches the pledger to an
  existing MP contact by name/email/phone and falls back to the generic donor
  when there is no match, so a pledge is never lost to a spelling difference.
- **Confirmation** — covers the form rather than replacing it, so the band keeps
  its height and the page does not jump. The form beneath is `inert`, focus moves
  to the confirmation, and Escape (or "Make another pledge") returns a blank form.

## API

Backed by the **giving** endpoints in perimeter-api. `POST /api/giving/pledges`
is public — the pledge form is an embedded public widget, so there is no auth
gate; production CORS restricts callers to perimeter.org origins, and
`/api/giving` is already in the API's widget path allowlist.

One thing to know if you touch the hook: that route is the one perimeter-api
route that unwraps its controller's `{ success, data }` result and returns the
bare `{ pledgeId, amount }` payload, so the generated OpenAPI type for
`createPledge` describes an envelope the wire format does not have.
`useCreatePledge` types its response off the operation's `['data']` member for
that reason.
